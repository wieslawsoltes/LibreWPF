# ProGPU Branch Plan for WPF Port Acceleration

## Reuse Policy

The ProGPU branch should add reusable native primitives and shim behavior only where they let the WPF port keep real managed WPF code on the active path. Rendering, text rasterization, shader effects, vector geometry, image upload, cache/lifetime, and backend resource fixes belong in ProGPU when the alternative would be a WPF-bridge workaround or managed-side pixel/vector emulation. XAML, controls, resources, styles/templates, routed events/commands, layout metadata, application lifetime, and theme dictionaries should stay in the WPF superproject and continue to use upstream managed WPF code.

## SDK Delivery Requirement

The deliverable shape is the public `LibreWPF.Sdk` package, a custom MSBuild SDK that existing WPF applications can select by changing only the project `Sdk`. The SDK must hide the portable WPF transport, ProGPU/Silk.NET package graph, runtime assets, and bootstrap registration behind MSBuild imports while preserving normal WPF `ApplicationDefinition`, `Page`, `Resource`, BAML, theme, code-behind, dependency-property, binding, command, layout, and control-manager behavior. Public NuGet and README branding should use `LibreWPF.*`, while source project names, namespaces, assembly names, target files, and runtime type identities remain unchanged unless a separate code migration is requested. Any required source or XAML edit in a normal app is a compatibility bug unless it is an explicitly documented Windows-only interop exception. ProGPU branch work should therefore favor native primitives and platform services that let this SDK contract keep upstream managed WPF code active, not managed bridge workarounds that customers would need to opt into. This is now a hard delivery criterion for the port: repo-local smoke apps, external package-mode harnesses, and CI/package validation should prove that app projects need no ProGPU-specific properties or source edits beyond the SDK selection.

## Reflection-Free Implementation Requirement

The WPF bridge product source is currently reflection-free by audit, so the active priority can return to SDK/sample validation and remaining runtime gaps while preserving that invariant. Product hot-path reflection should be treated as a porting bug unless it is explicitly transitional and has a documented removal path. Runtime reflection is permitted only as temporary scaffolding for diagnostics, compatibility probes, or transitional adapters. The target architecture remains typed, generated, or source-integrated access to WPF/MIL/resource/visual state, with rendering, clipping, hit testing, shader effects, text, cache metadata, DirectX shims, and platform services implemented in reusable ProGPU/Silk.NET layers instead of managed WPF bridge workarounds.

Near-term Showcase sample work must preserve that rule. If an Xceed, SciChart, SDK smoke, or basic WPF app needs state that is not available through typed contracts yet, the preferred fix is a source-built WPF portable contract or ProGPU-native primitive/shader/cache path, not another managed-side workaround. Product hot paths must stay reflection-free while broadening sample coverage unless a sample explicitly documents a non-product compatibility probe.

Retained invalidation performance work follows the same typed-seam rule. Baseline visual-child topology snapshots should allocate tracker-owned arrays only when the source topology actually changes; subscription refresh should reuse unchanged `IPortableVisualChildrenSource` snapshot arrays and prune stale snapshot owners with pooled scratch after traversal. Frame/version polling should compare live portable children against retained baselines directly and walk typed dependencies without building temporary child snapshot arrays. Retained graph traversal should also branch only when a source is actually `IEnumerable`, index list-like `IList`/`IReadOnlyList<object?>` collections directly during subscription, version polling, dependency enumeration, and retained dependency registration, and reserve `foreach` only for genuinely non-list enumerable fallbacks. Retained branch maps should also keep the normal one-visual source mapping and one-owner visual mapping in compact value-type storage, promoting to lists or hash-backed storage only for genuinely shared sources/visuals, should route tracker-owned reference-equality dirty-source sets through concrete `HashSet<object>` replay/invalidation helpers before generic collection handling, should index list-like dirty-source fallbacks when populating distinct source sets or reading a single source, should use `WpfVisualInvalidationTracker.LastDirtySource` as the single-source hint before enumerating a one-item dirty set, should classify promoted owner sets by scanning dirty sources when the dirty batch is smaller than the owner set, and should reuse map-owned single/multi replay-target snapshot lists instead of allocating replay-target arrays for multi-branch dirty frames. Render-data dependent-resource snapshots and MIL resource token setup should use shared empty storage for zero resources and index `IReadOnlyList<object?>` resources through retained dependency registration, invalidation dependency visiting, and resolver/registry construction. Text-heavy glyph-run replay should export source-built WPF glyph resources as `IPortableNativeGlyphRunSource`/`PortableNativeGlyphRun` when positions are available as `Vector2[]`, cache initialized glyph-run portable/native DTOs on the source-built `GlyphRun`, let ProGPU annotate those DTOs with resolved backend fonts, cache glyph origin/font/position arrays, reuse exact-sized native position arrays without copying, use indexed `GlyphPositions` loops in ProGPU command sinks, retained visual bounds accumulation, and drawing replay, and keep direct Y1/Y2 guideline scopes on inline command-sink values instead of allocating one/two-element arrays. This avoids per-cell `List<ProGpuVisual>`, owner `HashSet<object>`, fallback enumerable, generic dirty-source enumeration, replay-target array, unchanged visual-child snapshot arrays, empty dependent-resource array, dependent-resource `IEnumerable` traversal, promoted-owner full-set scans for small dirty batches, portable glyph point/advance round-trips, repeated glyph DTO array rebuilds, repeated glyph font-family resolution, glyph-position `foreach`, tiny guideline arrays, or wrapper allocations in Xceed/AvalonDock/DataGrid scroll and replay paths. This keeps large Xceed/AvalonDock/DataGrid trees from paying per-probe managed array churn while preserving WPF-owned child topology and avoiding bridge-local reflection.

Native WPF brush and pen adaptation should also stay cache-backed on the renderer side. Actual source-built `SolidColorBrush`, `LinearGradientBrush`, `RadialGradientBrush`, and simple solid `Pen` instances are weak-key cached as native ProGPU vector resources, with color/opacity/gradient-stop/transform/pen-property validation so mutable `Freezable` state refreshes without routing every Xceed/DataGrid draw through new portable DTO and vector object allocations. Absolute no-transform gradients should return the cached native gradient object directly; relative or transformed gradients may remap coordinates per draw bounds while reusing the validated native gradient stop array. Dashed pens and unsupported shapes continue through typed portable contracts or native ProGPU shader paths; do not add reflection or duck-typed `ToNative` probes to recover those cases.

Update: ProGPU `main` commit `304bbed19ad215b71403e3705993f6001b1de753` moves `GpuHitTestIndex.Build(...)` quadtree construction onto the caller's `ReadOnlySpan<GpuHitTestPrimitive>`/`ReadOnlySpan<GpuPathSegment>` input and copies only the durable arrays owned by the finished index. WPF package-mode cache builders already pass spans over their collected primitives/path segments, so paid Xceed DataGrid GPU hit-test cache rebuilds no longer allocate pre-build primitive/path-segment arrays just to compute bounds and populate the broad-phase tree.

Retained visual replay should also consume `IPortableVisualChildrenSource` directly by reading `TryGetPortableVisualChildCount(...)` once and indexing `TryGetPortableVisualChild(...)` in replay and retained content-bounds inference. Do not use `ExtractChildren(visual)` foreach traversal or custom `PortableVisualChildrenEnumerable`/`PortableVisualChildrenEnumerator` wrappers in `WpfVisualTreeRenderer`; that child walk is proportional to large Xceed/DataGrid tree size and should stay on direct typed calls.

Retained invalidation subscription refresh should also be coalesced. `WpfVisualInvalidationTracker` should request a refresh when typed invalidation, property, collection, or detected topology changes arrive, then rebuild subscriptions once when the dirty pass is consumed instead of clearing and resubscribing the full WPF graph for every Xceed/DataGrid event burst.

Retained invalidation version-change batches should keep list-owned dirty marking. `_changedSources` is reused across detection passes and should flow through an indexed `IReadOnlyList<object>` helper with no parallel generic `IEnumerable<object>` dirty-marking overload, avoiding interface-enumerator dispatch during Xceed/DataGrid retained replay invalidation. The helper must add the whole changed-source batch before raising `Invalidated`, because `ProGpuWpfCompositionTarget` consumes `DirtySources` synchronously to prepare retained replay targets and partial batches can misclassify branch fallback/replay work during Xceed/DataGrid event bursts.

Retained invalidation visual-state and visual-children comparisons should keep concrete dictionary signatures as well. `_visualStateSnapshots`, `_currentVisualStateSnapshots`, and `_visualChildrenSnapshots` are owned by `WpfVisualInvalidationTracker`; comparison helpers should receive those concrete dictionaries instead of `IReadOnlyDictionary<...>` so Xceed/DataGrid version-change scans avoid dictionary interface dispatch.

Geometry bounds inference should keep direct primitive replay on indexed list/array paths too. `WpfVisualTreeRenderer.TryGetLineSegmentBounds(...)` and similar replay helpers should index known `IReadOnlyList<T>`/array data instead of enumerating, so Xceed/DataGrid row, border, grid-line, and polyline geometry bounds do not allocate or dispatch through interface enumerators.

Primitive helper data computed while replaying local WPF geometry should be reused when the current shape still matches the cache. Local `MediaGeometry` line and polyline extraction should use a weak geometry-keyed cache for transformed line points and segment arrays, validate current raw path points plus transforms before reuse, return cached transformed helpers on unchanged shapes, and rebuild when mutable WPF geometry changes. The polyline cache should keep raw segment endpoints, the original start point, closed state, and transform as its validation fingerprint so cache hits do not transform each point again just to prove the shape is unchanged. This lets Xceed/DataGrid template geometry, borders, and grid-line resources share the same helper cache across generated render data, object render data, MIL decode, Drawing replay, retained bounds inference, and future GPU hit-test cache construction without depending on a full `Freezable` surface in the ProGPU PresentationCore shim.

Guideline snapping should keep the command-sink stack path indexed as well. `ProGpuCompositionCommandSink.SmallValueStack<T>` should expose top-down access for hot stack scans, and Xceed/DataGrid text/grid guideline snapping should use indexed `PeekAtDepth(...)` loops instead of enumerating `_guidelineStack`. Retained visual guideline wrappers should also be weak-key cached per portable visual and rebuilt only when the typed snapping-guideline flags or array identities change, so repeated retained replay of text/grid-heavy Xceed/DataGrid visuals does not allocate wrapper objects while mutated guideline array contents still flow through the existing typed arrays.

Shader-effect sampler traversal should stay indexed over source-built and ProGPU-native sampler arrays. `WpfEffectMapper` should cache `effect.Samplers` into a local and index it during validation/adaptation, `WpfVisualInvalidationTracker` should do the same while visiting sampler brush/image dependencies, `WpfShaderEffectParams` should index its native `Samplers` array during texture queries/cache-key work, and command-sink guideline arrays should use indexed loops too.

DrawingGroup child traversal should stay indexed too. `WpfDrawingReplay` should read source-built `IPortableDrawingGroupChildrenSource` counts once, index children through `TryGetPortableDrawingGroupChild(...)`, and use the same indexed helper for `PortableDrawingGroupState.Children` fallback arrays during replay and content-bounds inference; do not reintroduce `ExtractChildren(drawingGroup, ...)` foreach wrappers.

This requirement does not reduce managed WPF reuse. The port should keep upstream WPF managers, controls, XAML, resources, themes, layout, binding, routed events, commands, and document systems active, while replacing only the Windows-only or MIL/native seams needed to run cross-platform through ProGPU.

Typed bridge contracts must not expose shim-owned WPF structs or classes when package-mode apps load the real WPF transport assemblies. Use primitive values or neutral DTOs for cross-assembly bridge callbacks, and add source-integrated WPF interfaces/factories for hot paths instead of `Assembly.GetType`, `Activator`, reflected properties, reflected events, or expression-built delegate shims. Non-2D RW textures and broader typed-format selection remain fail-closed follow-up work inside `ProGPU.DirectX`.
- DirectX HLSL bytecode descriptors now expose a reusable reflection surface before full bytecode execution is connected. `ProGpuDirectXShader.BytecodeInfo` classifies DXBC containers, raw DXIL headers, and raw DXIL bitcode, parses DXBC chunk tables, extracts tokenized shader program kind/model from `SHDR`/`SHEX`/`DXIL`, reflects `ISGN`/`ISG1`, `OSGN`/`OSG5`, and `PCSG` signatures, and reflects `RDEF` resource bindings. Bytecode still remains metadata-only for native module creation until a compiler/import path or binary-compatible Direct3D facade is wired in, but real shader blobs can now be inspected and routed without managed WPF shader rewrites.
- Reflected DirectX shader bytecode can now derive native input-layout descriptors. `ProGpuDirectXShaderBytecodeInfo.TryCreateInputLayoutDescriptor(...)` converts non-system `ISGN` parameters into packed `DxInputElementDescriptor` entries, preserves shader locations from signature registers, supports configurable input slot/class/step rate, maps float/uint/sint scalar and vector component masks to DirectX shim formats, and rejects unsupported masks instead of guessing. This prepares SciChart/SharpDX adapter work to create ProGPU vertex layouts from compiled shader metadata without WPF-side vertex declaration rewrites.
- Reflected DirectX input-layout derivation is now part of graphics pipeline state. `ProGpuDirectXGraphicsPipeline.EffectiveInputLayout` uses an explicit descriptor layout when present, otherwise derives the layout from vertex shader bytecode metadata, exposes support/failure metadata, keys native pipeline creation on that effective layout, and makes immediate-context `SetGraphicsPipeline(...)` publish the same layout as current input state. This keeps compiled-shader SciChart/SharpDX adapter paths from duplicating signature parsing or context synchronization.
- Reflected DirectX shader bytecode can now derive native binding requirements from `RDEF` metadata. `ProGpuDirectXShaderBytecodeInfo.TryCreateBindingRequirements(...)` maps constant buffers, texture/structured/byte-address SRVs, samplers, and typed/structured/byte-address UAVs onto ProGPU binding kinds with deterministic native binding numbers from the shared DirectX binding map while preserving raw type, return, dimension, and flag metadata. Unknown binding types fail closed so adapters can reject unsupported compiled shader resource declarations without managed WPF rewrites.
- Reflected DirectX binding requirements now surface on shader and pipeline metadata. `ProGpuDirectXShader.ReflectedBindingRequirements` carries valid bytecode requirements plus fail-closed support/failure metadata, while `ProGpuDirectXGraphicsPipeline` and `ProGpuDirectXComputePipeline` aggregate stage requirements so SciChart/SharpDX adapters can preflight resources against a compiled DirectX pipeline without duplicating bytecode parsing or native-slot derivation.
- DirectX context binding preflight now validates current context resources against reflected shader/pipeline requirements. `ValidateGraphicsPipelineBindings(...)` and `ValidateComputePipelineBindings(...)` report unsupported reflection or missing constant-buffer/SRV/sampler/UAV slots, recorded draw/dispatch commands carry the validation result for diagnostics, array binding counts are checked slot-by-slot, and `ProGpuDirectXDeviceOptions.EnableValidation` turns those diagnostics into early exceptions.

This prepares palette, marker atlas, surface/volume slice, and 3D chart material shaders without falling back to managed WPF texture rewrites.

## Decisions

- Make reflection-free bridge/backend implementation a hard near-term cleanup gate. Existing reflection-heavy WPF visual/MIL/resource adapters may remain only as transitional scaffolding while typed seams, generated accessors, source-integrated WPF internals, and ProGPU-native scene/vector/text/shader/platform primitives are built; new feature work should not deepen reflection dependency unless it includes an explicit removal path.
- Use typed render-data sink contracts instead of runtime provider probing. `IPortableRenderDataDrawingContextSink` and `PortableRenderDataDrawingContextSinkProvider` are now the model for WPF-to-ProGPU render-data redirection: the port should add source-integrated WPF seams that both real `PresentationCore` and the ProGPU shim expose, then keep any cross-assembly-load-context proxying in validation harnesses only. Do not reintroduce reflection/expression-built provider delegates or per-instruction `MethodInfo.Invoke` forwarding in the product bridge.
- Prefer ProGPU-owned native capability interfaces over shim-only method reflection. Shim geometry path extraction now flows through `ProGPU.Scene.INativePathGeometrySource`, which lets `ProGPU.Wpf` consume package-mode native vector paths without reflecting for `Geometry.Draw(...)`. Real WPF geometry extraction now flows through the signed `ProGPU.Wpf.Interop` DTO contract: source-built `PresentationCore.Geometry` implements `IPortableGeometryPathSource`, exports path figures, arcs, transforms, bounds, and combined-geometry operation trees, and `ProGpuCompositionCommandSink` consumes that typed contract without `System.Reflection`, non-public `BindingFlags`, public `GetProperty(...)` object-shape reads, or reflected method invocation. Dynamic guideline extraction now follows the same contract pattern through `IPortableGuidelineSetSource`/`PortableGuidelineSet` instead of reflected `GuidelineSet` property reads. Transform matrix extraction follows it through `IPortableTransformMatrixSource`/`PortableMatrix3x2`; solid and linear/radial gradient brush extraction follows it through `IPortableBrushSource`/`PortableBrush`; pen extraction follows it through `IPortablePenSource`/`PortablePen`; `DrawingVisual` plus `UIElement` retained-content extraction follows it through `IPortableDrawingContentSource`; `GeometryDrawing`, `ImageDrawing`, `GlyphRunDrawing`, and `DrawingGroup` replay state follow it through source-specific portable drawing state contracts; tile-brush and shader-effect dependencies follow `IPortableTileBrushSource` and `IPortableShaderEffectSource`; core `Visual` state follows it through `IPortableVisualStateSource`; core visual content/descendant bounds follow it through `IPortableVisualBoundsSource`; and `UIElement`/`FrameworkElement` layout state follows it through `IPortableVisualLayoutStateSource`, so source-built real WPF can expose visual content, visual bounds, leaf drawing state, drawing-group children/state, brush/effect sampler dependencies, child traversal, offset, transform, clip, scrollable clip, opacity, opacity mask, arranged size, clip-to-bounds, computed layout clips, and host root render-size reconciliation without private-field, protected-property, public layout-property, object-shape, or layout-method reflection on the normal hot path. Retained invalidation should not use a generic reflected reference-property scanner; missing resource edges are source-built interop contract gaps, not bridge reflection work.
- Apply the same typed/source-integrated pattern to the remaining reflection-heavy bridge areas. Retained visual traversal/state, tile/image/visual/drawing brush resource adaptation, transform/resource construction, image-source upload, invalidation, remaining platform-service registration, and platform/DirectX facade seams should move behind real WPF source hooks, shared portable contracts, generated accessors, or ProGPU-native services rather than expanding managed bridge reflection. Portable service registration for clipboard, media-context render wakeup, window activation, launcher, message-box, and file-dialog integration now requires typed `PortableWpfServiceRegistry` registrars and fails closed when a source assembly does not publish them; do not reintroduce reflected `Portable*Service.Register(...)` method discovery. Main-window query, window close/cancel, media-context render wakeup, dispatcher flush, activation-state, input dispatch/routing, and drag/drop service routing must also stay on typed `IPortableWindowActivationServiceRegistrar` operations and fail closed when unavailable. Remaining activation `System.Reflection` references are public assembly-keyed bootstrap handles plus `TargetInvocationException` unwrapping around host callbacks.
- Keep feature work that accelerates WPF rendering fidelity in the ProGPU branch when it improves the backend model directly, instead of compensating in the WPF bridge.
- Keep WPF arc semantics in ProGPU vector primitives. The WPF bridge may adapt WPF types, but affine arc math, sweep flipping, and shader-rasterized arc records belong in `ProGPU.Vector`/`ProGPU.Scene`.
- Preserve API-level rounded-rectangle radii before they reach the bridge. WPF `radiusX`/`radiusY` and Skia per-corner radii should remain native ProGPU command/path data, with only uniform scalar cases using the compositor's fast rounded-rect primitive path.
- Preserve host-level per-corner corner radii as geometry when the host platform API cannot express them as independent radii. Do not collapse asymmetric `CornerRadius` values to a uniform max-radius clip in host controls, because that clips square corners that WPF/Avalonia semantics leave uncut.
- Keep WPF/WinUI path API shims from erasing arcs before rendering. Parsed `ArcSegment` values should stay native ProGPU arcs, and WPF `Geometry.Transform` should be passed as command transform metadata so ProGPU owns affine arc evaluation. Degenerate arcs may fall back only inside the ProGPU vector layer where shader parameters cannot be produced.
- Prefer fixed-quad shader primitives for WPF-compatible arc strokes. CPU flattening should be limited to degenerate arcs that cannot produce valid shader parameters; parametric strip tessellation should not be reintroduced as a WPF bridge workaround.
- Preserve WPF clip geometry as ProGPU geometry masks whenever the source geometry can be represented as a ProGPU vector path. Rectangular fallback is acceptable only for unsupported geometry forms, and rotated/sheared fallback bounds must still include all transformed corners.
- Keep WPF geometry API shims non-mutating and query-correct. Geometry bounds must apply the current transform through ProGPU vector helpers before rendering, not by copying state during `Draw()`, because WPF layout, hit-testing, clipping, and retained cache sizing commonly query bounds before render replay.

- Prefer adding reusable ProGPU primitives for WPF concepts that also benefit other frontends: exact path stroking, gradient tables, texture sampling modes, text flags, mesh extensions, image effects, and retained resource lifetime helpers.
