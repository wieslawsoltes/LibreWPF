# ProGPU WPF Win32 Abstraction Plan

## Rule

The ProGPU port lane should not add new direct Win32 calls. Existing WPF Win32 calls must either move to Silk.NET/ProGPU where they are rendering or windowing concerns, or move behind local platform interfaces where they are OS services.

## Initial Interfaces

`src/ProGPU.Wpf/Platform` introduces:

- `IWpfClipboard`
- `IWpfCursorService`
- `IWpfDispatcherService`
- `IWpfDispatcherOperation`
- `IWpfDragDropService`
- `IWpfFileDialogService`
- `IWpfInputService`
- `IWpfLauncher`
- `IWpfMonitorService`
- `IWpfPlatformServices`
- `IWpfTimerService`
- `IWpfTimer`
- `IWpfWindowEventService`
- `CrossPlatformWpfPlatformServices`
- `ProcessWpfFileDialogService`
- `ProcessWpfLauncher`
- `QueuedWpfDispatcherService`
- `SilkNetWpfCursorService`
- `SilkNetWpfDragDropService`
- `SilkNetWpfInputService`
- `SilkNetWpfMonitorService`
- `SilkNetWpfWindowEventService`
- `ThreadPoolWpfTimerService`

The default host implementation uses `CrossPlatformWpfPlatformServices`. Shell launching is implemented with `ProcessStartInfo.UseShellExecute`, which is the portable .NET replacement for simple `ShellExecute`-style URI and file open requests. Real WPF `AppSecurityManager` now routes non-Windows safe hyperlink/browser launch and default-browser launch through `PortableLauncherService`, which `WpfPortableWindowActivation` registers against `IWpfLauncher`, so document/navigation managers can keep WPF's launch policy without entering `ShellExecute` or `ShellExecuteEx` outside Windows. Clipboard text access is implemented by `ProcessWpfClipboard` behind `IWpfClipboard`, selecting `pbcopy`/`pbpaste` on macOS, PowerShell `Set-Clipboard`/`Get-Clipboard` on Windows, and `wl-copy`/`wl-paste` with `xclip`/`xsel` fallbacks on Linux. File open, file save, and folder pickers are implemented by `ProcessWpfFileDialogService` behind `IWpfFileDialogService`, selecting `osascript` on macOS, PowerShell Windows Forms dialogs on Windows, and `zenity` with `kdialog` fallback on Linux. Low-level key, text, mouse, and wheel input is implemented by `SilkNetWpfInputService` behind `IWpfInputService`, with `ProGpuWpfWindowHost` forwarding normalized events through `InputReceived` and `WpfPortableWindowActivation` delivering them to explicit `OnPortableInput(WpfInputEventArgs)` or `HandlePortableInput(WpfInputEventArgs)` transition handlers on the active WPF-shaped window. Cursor updates are implemented by `SilkNetWpfCursorService` behind `IWpfCursorService`, mapping WPF-shaped cursor names to Silk.NET `StandardCursor` values. Dispatcher posting is implemented by `QueuedWpfDispatcherService` behind `IWpfDispatcherService`, preserving owner-thread processing and WPF-shaped priority ordering while raising `WorkAvailable` when callbacks are queued; `ProGpuWpfWindowHost` observes that event, drains owner-thread work immediately when safe, and otherwise wakes the event-driven Silk.NET loop with `IWindow.ContinueEvents()` so worker-thread posts are serviced by the next owner-thread pump. `DispatcherWpfRenderScheduler` maps coalesced render requests and delayed MediaContext animation ticks onto a one-shot timer plus `Render` dispatcher-priority callback, and `IWpfRenderScheduler` feeds the host's guarded scheduler wakeup path, native `ContinueEvents()` fallback, and `ProGpuWpfFrameState` gate so unchanged retained frames can be skipped at the Silk.NET render boundary when no explicit draw callback or pending render request requires work. Portable drop payload intake is implemented by `SilkNetWpfDragDropService` behind `IWpfDragDropService`, mapping Silk.NET file drops into `WpfDragDropEventArgs`, forwarding them through `ProGpuWpfWindowHost.DragDropReceived`, and letting `WpfPortableWindowActivation` deliver the payload to explicit transition handlers on the active WPF-shaped window. Activation/deactivation and external file-drop intake is implemented by `SilkNetWpfWindowEventService` behind `IWpfWindowEventService`, with the host forwarding normalized events through `WindowEventReceived`. Monitor enumeration is implemented through Silk.NET `IWindowPlatform.GetMonitors`, mapping `IMonitor` bounds, primary identity, typed DPI-scale provider values when supplied, and video-mode-to-bounds scale into `WpfMonitorInfo`. Timer creation is implemented by `ThreadPoolWpfTimerService` behind `IWpfTimerService`, using `System.Threading.Timer` for portable one-shot and repeating timers.

Real WPF `MediaContextNotificationWindow` now keeps its hidden HWND and DUCE window-message notification setup Windows-only. On non-Windows it preserves construction/disposal shape but skips `RegisterWindowMessage`, hidden `HwndWrapper` creation, MILCore DWM content attach/detach, and channel `SetNotificationWindow(...)`. Real WPF `MediaContext` also routes performance-counter access through a local clock boundary: Windows keeps QPC, while non-Windows uses `Stopwatch` counts and frequency. Real WPF `MediaSystem` keeps media-context lifetime bookkeeping on non-Windows but returns disconnected before MILCore version checks, partition-manager startup, DUCE transport/channel creation, RDP hardware toggle setup, redirection notifications, and partition-manager shutdown. `PortableMediaContextRenderService` is the non-Windows render wakeup boundary: it lets `MediaContext.PostRender()` and `ScheduleNextRenderOp(...)` wake the Silk.NET host, carry delayed animation tick timing, drain WPF `DispatcherPriority.Render` operations, and run managed `TimeManager`/render callbacks even while DUCE channels are disconnected. Full in-assembly `MediaContext` integration still needs a portable channel notification source instead of DUCE HWND messages.

Real WPF `HwndTarget` remains the Win32 composition target, but its static window-message registration is now Windows-only and non-Windows construction fails before session, HWND, or MIL initialization. This keeps the public type loadable while making the remaining replacement boundary explicit: non-Windows window ownership must come from a ProGPU/Silk.NET composition target rather than an HWND-backed target. Real WPF `PortableCompositionTarget` is the first in-assembly non-HWND target boundary for that replacement: it owns a root visual and device transforms without DUCE resource creation, and `CompositionTarget` now gates DUCE root cleanup behind `UsesDuceComposition`. Real WPF `PortablePresentationSource` wraps that target with `PresentationSource` root/source tracking and render requests, and `ProGpuWpfWindowHost` now owns typed `WpfPortablePresentationSourceBridge` attachment through `IPortablePresentationSourceHost` and `PortablePresentationSourceHost.Create(...)`. `PortableWindowActivationService` is the real `PresentationFramework` non-Windows activation boundary: `Window.Show` tries a registered portable activation before HWND creation, stores the returned activation object for show/hide/window-state/title/client-size/position/topmost/border/close/run/dispose delegation, forwards focus-derived activation state through existing `Window.HandleActivate(bool)`, and `Application.Run` skips the hidden parking `HwndWrapper` on non-Windows before handing event-loop ownership to the registered Silk.NET host. Portable `Window.SizeToContent` sizing stays in WPF layout: the active portable window measures and arranges its content, clamps through existing `WindowMinMax`, then forwards startup and live content-size changes to the ProGPU/Silk.NET host through `PortableWindowActivationService.SetClientSize(...)` instead of entering `HwndSource.SizeToContent`. The real XAML runtime harness now verifies root `Keyboard.Focus(...)`/`Keyboard.ClearFocus()` over the shown portable source; child control focus still requires completing the non-HWND window template/content-hosting visibility path. `WpfPortableWindowActivation.TryRegisterPresentationFrameworkActivation(...)` is now a typed portable-service registration helper using `PortableWpfServiceRegistry`; native host close callbacks invoke WPF `Close()` and, when WPF cancels `Closing`, clear Silk.NET `IWindow.IsClosing` and keep the ProGPU target alive.

Real WPF `MessageBox` now has a `PortableMessageBoxService` boundary for non-Windows dialog requests. Windows still uses the upstream `UnsafeNativeMethods.MessageBox(...)` path, including HWND owner lookup and Win32 style flags. Non-Windows keeps WPF's managed enum validation, service-notification owner checks, default-button mapping, and public overload surface, but routes to a registered portable handler before any Win32 call. If no handler is registered, it returns the requested default result or WPF's first-button fallback so basic apps can keep running. `WpfPortableWindowActivation` registers the service through the typed `IPortableMessageBoxServiceRegistrar` and forwards neutral `PortableMessageBoxRequest` DTOs into `CrossPlatformWpfPlatformServices.Instance.MessageBoxes`; the default `ProcessWpfMessageBoxService` selects PowerShell Windows Forms on Windows hosts, `osascript` on macOS, and `zenity` with `kdialog` fallback on Linux. SDK smoke harnesses explicitly replace the handler with deterministic fallback callbacks before asserting no-owner and owner overload results so automated validation does not open native modal UI.

Real WPF `SystemParameters` now keeps the public focus-border metric/resource-key surface usable on non-Windows. `FocusBorderWidth`, `FocusBorderHeight`, `FocusHorizontalBorderHeight`, and `FocusVerticalBorderWidth` retain WPF's managed cache invalidation and Windows-native lookup on Windows, but use a conservative one-pixel fallback outside Windows before any `SystemParametersInfo(...)` or `GetSystemMetrics(...)` call. This is a bring-up fallback for themes and controls until monitor/theme/accessibility metrics are supplied by a local platform service.

## Mapping

- HWND creation, render target ownership, resize, frame coalescing, and present: Silk.NET + `ProGpuWpfWindowHost`.
- Real WPF `HwndTarget`: Windows-only HWND composition target; non-Windows type loading is safe, but construction fails fast until a Silk.NET-backed `CompositionTarget` replaces it.
- Real WPF `PortableCompositionTarget`: non-HWND managed root/device-transform target; no DUCE resource creation; intended base for the Silk.NET/ProGPU-backed presentation source.
- Real WPF `PortablePresentationSource`: non-HWND `PresentationSource` that owns `PortableCompositionTarget`, participates in current-source tracking, raises root/source changes, and emits render requests without entering the DUCE render loop.
- `WpfPortablePresentationSourceBridge`: typed adapter that creates or binds the real portable source through `IPortablePresentationSourceHost`, mirrors its root into `ProGpuWpfWindowHost.WpfRootVisual`, forwards device scale/client size, and maps source render requests into the Silk.NET host scheduler. The host owns bridge lifetime, replacement, root sync, and per-frame DPI updates.
- Real WPF `PortableWindowActivationService`: `PresentationFramework` registration and lifetime boundary for non-Windows `Window.Show`, `Hide`, `WindowState`, `Title`, client size, `SizeToContent` measured startup and live relayout size, position, focus-derived `Activated`/`Deactivated`, `Closing`, and `Application.Run`; registered delegates create the portable host/source, handle show/hide/window-state/title/client-size/position/topmost/border/close/run, and close/dispose the activation without a WPF-to-ProGPU compile-time dependency.
- Real WPF `PortableLauncherService`: `PresentationFramework` registration boundary for non-Windows `AppSecurityManager` browser/hyperlink/default-browser launch; registered delegates receive WPF's managed launch request and return whether the platform opened it, allowing ProGPU to use `IWpfLauncher` without direct `ShellExecute`/`ShellExecuteEx` calls outside Windows. The external SDK smoke now validates this service is SDK-bootstrap enabled and verifies URI/target-frame/top-level request shape with a deterministic launcher handler so package-built apps do not need app-side ProGPU launcher code.
- Real WPF `PortableMessageBoxService`: `PresentationFramework` registration boundary for non-Windows `MessageBox.Show(...)`; registered delegates receive WPF's managed request object and return a WPF `MessageBoxResult`, allowing the ProGPU platform service to show native/process-backed OS dialogs without direct `user32!MessageBox` use outside Windows.
- Real WPF `SystemParameters` focus-border metrics: Windows keeps `SystemParametersInfo(...)`/`GetSystemMetrics(...)`; non-Windows uses deterministic managed fallback values so WPF theme/resource lookup can initialize without direct `user32` calls.
- `WpfPortableWindowActivation`: transition bootstrap that derives `ProGpuWpfWindowOptions` from `IPortableWindowStateSource`/`PortableWindowState`, attaches the host-owned portable source, uses the top-level window as the root visual, registers real WPF portable services through typed `PortableWpfServiceRegistry` registrars, maps live title/client-size/position/topmost/border changes and native hide/minimize/maximize requests onto Silk.NET host state, accepts WPF startup and live `SizeToContent` measured client sizes through the same client-size delegate, maps focus-derived host activation/deactivation events back through typed activation callbacks, maps native host close callbacks back to WPF `Close()` with cancel propagation through `IWindow.IsClosing`, and forwards normalized input plus external file-drop payloads through typed portable activation/input services.
- D3D device/swapchain: ProGPU `WgpuContext`.
- MIL composition target: `ProGpuWpfCompositionTarget`.
- MIL geometry bounds and hit tests: Windows keeps `MilUtility_PathGeometryBounds`, `MilUtility_PolygonBounds`, and `MilUtility_PolygonHitTest`; non-Windows real `PresentationCore` now routes `PathGeometry` bounds through source-included `ProGPU.Vector.PathGeometry.TryGetBounds(...)`/`ArcSegmentGeometry` after WPF path parsing, line/polygon bounds through `ProGPU.Vector.PolygonGeometryBounds`, generic bounds/tolerance hit queries through `ProGPU.Vector.BoundsHitTesting`, solid line fill/stroke containment through `ProGPU.Vector.LineGeometryHitTesting`, rectangle fill/stroke containment through `ProGPU.Vector.RectangleGeometryHitTesting`, and ellipse fill/stroke containment through `ProGPU.Vector.EllipseGeometryHitTesting`. Exact WPF-compatible dashed line and complex path point/stroke containment remains a ProGPU/native vector follow-up.
- Drawing commands: `IWpfCompositionCommandSink`, backed by `ProGpuCompositionCommandSink`.
- WPF Viewport3D offscreen rendering: `WpfViewport3DSceneBridge` consumes source-built `IPortableViewport3DSceneSource` camera, light, mesh, material, transform, and viewport DTOs, compiles them into ProGPU's `Mesh3D` extension, and composites the cached offscreen texture through the normal 2D command stream.
- File dialogs: `ProcessWpfFileDialogService`, with a later option to replace process-backed commands with native per-OS APIs behind the same `IWpfFileDialogService` boundary.
- Clipboard: `ProcessWpfClipboard`, with a later option to replace process-backed commands with native per-OS APIs behind the same `IWpfClipboard` boundary.
- Input: `SilkNetWpfInputService` for low-level keyboard, text, mouse, and wheel events, `ProGpuWpfWindowHost.InputReceived` for host delivery, and `WpfPortableWindowActivation` for forwarding into WPF's portable input handler; root and child `TextBox` keyboard focus now work through WPF `Keyboard.Focus(...)` over `PortablePresentationSource`, compiled `Window.InputBindings` can be activated by portable `Ctrl+F6` key input through WPF `InputManager`/`CommandManager`, basic portable text input now reaches WPF `TextCompositionManager`/`TextEditorTyping` to mutate a focused `TextBox`, and portable mouse move/down/up/wheel now reaches WPF `MouseDevice`/`ButtonBase` enough to capture/release the button, raise generated XAML `GotMouseCapture`/`LostMouseCapture`, fire generated XAML `Click` handlers, and raise a generated XAML `MouseWheel` handler with WPF's normalized one-line delta. On high-DPI hosts, pointer coordinate space is classified from the native Silk `IWindow.Size` against the resolved ProGPU render-surface geometry first, so framebuffer-sized native windows normalize every pointer event to WPF DIPs even when the event lies inside the upper-left logical quadrant; per-event logical-bound thresholding remains only as a fallback for ambiguous backends. Compiled and loose SDK XAML now preserve WPF `InputMethod.InputScope` metadata in the managed object model, and the external SDK smoke validates `InputLanguageManager` plus `InputMethod` preferred IME attached metadata and portable non-Windows manager state. Native IME/touch-keyboard and language-profile services should consume that metadata later. IME, portable stylus/tablet support, and remaining focus/navigation/advanced capture edge cases remain higher-level porting steps.
- Drag/drop: `SilkNetWpfDragDropService` for external file-drop payloads surfaced as WPF-shaped drop events, with `WpfPortableWindowActivation` delivering those payloads to `OnPortableDrop`, `OnPortableFileDrop`, or `DropFiles` transition handlers when present; full WPF routed drag/drop, drag enter/over/leave, data-object negotiation, and effects remain higher-level porting work.
- Activation and file drop: `SilkNetWpfWindowEventService` for focus-derived activation/deactivation and external file-drop window events.
- Monitor/DPI: `SilkNetWpfMonitorService` for monitor bounds, primary monitor identity, explicit typed per-monitor scale when supplied, and video-mode-to-bounds DPI inference; Silk.NET framebuffer/logical-size data remains the active frame DPI scale. The ProGPU WPF host now normalizes Silk.NET native window-size and resize reports against `IWindow.FramebufferSize`, cached WPF client DIPs, monitor DPI scale, and the arranged WPF root `RenderSize` before updating the WPF logical client cache, even before WPF target attachment, with a conservative inferred-scale fallback when monitor scale is unavailable during startup. This keeps WPF layout in DIPs when macOS/Retina reports framebuffer-sized native dimensions and prevents the SDK smoke content from shifting into the upper-left physical quadrant.
- Cursor: `SilkNetWpfCursorService` maps WPF-shaped cursors onto Silk.NET `StandardCursor` values and applies them through Silk.NET mouse cursor objects.
- Window position: WPF keeps `Window.Left`, `Window.Top`, `_actualLeft`, `_actualTop`, and `LocationChanged` in `PresentationFramework`; non-Windows live moves route through `PortableWindowActivationService.SetPosition(...)` to `ProGpuWpfWindowHost.SetPosition(...)`, which applies Silk.NET `IWindow.Position` instead of calling `SetWindowPos`.
- Window border/resizability: WPF keeps `Window.ResizeMode`, `WindowStyle`, `WindowChrome`, resize-grip metadata, and custom-chrome semantics in managed `PresentationFramework`. The portable activation bridge translates initial and live `ResizeMode`/`WindowStyle` values through `PortableWindowActivationService.SetWindowBorder(...)` into `ProGpuWpfWindowHost.WindowBorder`, which maps to Silk.NET `WindowOptions.WindowBorder`/`IWindow.WindowBorder` for fixed, resizable, or hidden native borders. Deeper custom chrome, resize hit-testing, system menu, and caption-button parity remain native decoration-service work.
- Dispatcher posting and render scheduling: `QueuedWpfDispatcherService` queues callbacks by WPF-shaped priority, raises `IWpfDispatcherService.WorkAvailable` after enqueue, and processes callbacks on the owning thread from host wakeups, `ProGpuWpfWindowHost.ProcessDispatcherQueue`, `DoEvents`, Silk.NET update callbacks, and render callbacks; `DispatcherWpfRenderScheduler` uses `IWpfTimerService` plus `WpfDispatcherPriority.Render` to preserve WPF-style invalidation requests and delayed animation ticks until the host renders or its unchanged-frame gate can safely skip work. The host observes dispatcher and scheduler wakeups, requests a non-reentrant Silk.NET render pass when it is already on the dispatcher owner thread, and falls back to `IWindow.ContinueEvents()` to wake the event-driven native loop when work arrives from a worker/timer thread or during an active render.
- MediaContext notifications: Windows keeps the original hidden HWND notification window; non-Windows `MediaContextNotificationWindow` is a no-op until DUCE channel messages are replaced by a ProGPU/Silk.NET notification source.
- MediaContext clock: Windows keeps `QueryPerformanceFrequency`/`QueryPerformanceCounter`; non-Windows uses `Stopwatch.Frequency`/`Stopwatch.GetTimestamp()` behind the same WPF count-to-tick conversion helpers.
- MediaSystem/MIL transport: Windows keeps MILCore partition management and DUCE transport/channel creation; non-Windows keeps lifetime bookkeeping but skips MIL startup/shutdown and channel creation until a ProGPU/Silk.NET transport is wired.
- Timers: `ThreadPoolWpfTimerService` for portable one-shot and repeating timers used by render scheduling, MediaContext animation ticks, hover, and dispatcher scheduling bridges.
- Shell launch: `ProcessWpfLauncher`, using local OS shell association through `ProcessStartInfo.UseShellExecute`.

## Next Steps

1. Harden the process-backed clipboard and file dialog services or replace them with native per-OS implementations behind the same interfaces.
2. Complete portable window lifecycle integration beyond the first `Window.Show`, `Hide`, `WindowState`, title/client-size/position/topmost/border updates, startup and live `SizeToContent`, root/child `Keyboard.Focus(...)`, focus-derived `Activated`/`Deactivated`, normalized keyboard/text/mouse/wheel input payload forwarding, first routed `ButtonBase.Click`, first routed `MouseWheel`, basic WPF mouse capture/release routed events, real `TabControl` selected-content generation, `Closing` cancellation, and `Application.Run` bridge: remaining advanced capture/focus edge cases, app shutdown edge cases, and host disposal ordering.
3. Add IME and portable stylus/tablet handling, full routed drag/drop over `IWpfDragDropService`, map real WPF `MediaContext` channel notifications onto a portable notification source, deepen native event-loop marshalling beyond the current guarded host `DoRender()`, dispatcher `WorkAvailable`, and Silk.NET `ContinueEvents()` bridges, and deepen dirty-region/native invalidation policy behind local interfaces.
4. Replace `MS.Win32` usages in rendering-adjacent code with the service interfaces.
5. Keep Windows-specific compatibility behavior isolated in the Windows implementation.
